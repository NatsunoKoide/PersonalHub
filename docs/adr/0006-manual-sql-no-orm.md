# 手写 SQL，不引 ORM

# Status

accepted

# Decision

数据访问全部用 sqlite3 加手写 SQL，参数化查询，行用 `sqlite3.Row` 转成字典返回。不引 SQLAlchemy、peewee 或任何查询构造器。

# Why

用户明确要求「小数据库即可，不增加其他数据库插件」。加上 ORM 就等于把一个能在十年后直接读的 `.sql` 迁移链换成了依赖某个包版本的模型定义，一旦包停更，数据还在但代码打不开。这个项目的查询都是几十行的聚合和区间扫描，手写 SQL 反而更短也更清楚。

# Consequences

- 每个仓库模块要自己保证参数化，禁止字符串拼接 SQL。
- 迁移脚本是纯 `.sql` 文件，可以用任何 sqlite 工具直接打开执行，不依赖本项目代码。
- 返回的字典里的日期一律是 `YYYY-MM-DD` 字符串，跨到 JS 边界时无需转换。
