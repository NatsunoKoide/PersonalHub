# ADR 0008：界面走设计令牌，热量层先撤

## 状态

已接受（2026-10-24，v1.2.0）

## 背景

两件事在 v1.2.0 一起落地。

**热量。** v1.1.0 做了内置食物热量表和每日热量上限，用户看完后的反馈是
「不用记录卡路里，先只是单纯记录一下吃了什么」。这个判断是对的：减脂参考
本来就不需要精确到千卡，估算带来的心理负担比收益大；而中文食物没有可靠的
免费公开 API，精确也做不到。

**界面。** 用户还没看过前端就要求「用专业的 UI 设计师眼光优化」。此前样式是
边写边加的：圆角有 8/9/10/12/14 五种，颜色散在 views.js 的模板字符串里，
金额配色用的是支出红、收入绿（西方习惯）。

## 决策

**热量：撤界面，留数据。** `meals.kcal` 列与 `foods.py` 的 `kcal_100g` 都保留，
只是不再有任何界面读它。理由：删表要写迁移、删数据要重写 200 行，而用户说的
是「先」不做——留着的成本是零，删掉的成本是重写。想恢复时改 `diet.get_day`
和 `foods.as_dict` 即可，不动表结构。

`foods.py` 换个身份：从「算热量」变成「常见菜名库」，点一下把菜名填进某一餐。
快捷短语保留，定位是用户自己的常吃项（「楼下那家牛肉面」），与内置菜名表互补。

**界面：令牌化。** 所有视觉决策收敛到两处：

- `src/ui/styles.css` 的 `:root` 放颜色、字号、间距、圆角、阴影；
- `src/ui/charts.js` 的 `PALETTE` 放图表分类色，与令牌同源。

视图模板里不再写十六进制颜色。改风格只改令牌，组件规则不动。

**配色方向。** 金额按国内习惯：收入/向上 = 红，支出/向下 = 绿。超支和节假日
红字走 `--danger` 的警示语义，和方向色分开，免得「支出是绿的」和「超支是红的」
在同一屏上互相打架。

## 后果

- 换肤（包括以后做深色模式）是一次令牌替换，不是逐组件改。
- 年度热力图的数据源从「热量」换成「饮食」（当天记了几餐），语义反而更贴合
  「记录吃了什么」。
- 日历格子上多了一个 🍽 标记。
- 撤掉的入口：每餐的热量输入框、当日热量进度条、每日热量上限、`food_kcal`
  接口。都从 API 层移除，不留死代码——只有底层数据留着。
