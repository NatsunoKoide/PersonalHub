# OKR 进度由关键结果加权算出，允许手动覆盖

# Status

accepted

# Decision

目标（O）本身不存进度数字，进度由它下面的关键结果按权重加权算出：每个 KR 的完成度 = (当前值 − 起始值) / (目标值 − 起始值)，再按权重加权平均。目标上另留一个可空的手动覆盖字段，填了就压掉算法结果。

# Why

手动拖滑块最省事，但数字全凭感觉，一年后回看没有可信度；打勾式对「减脂 10 斤」这类连续量纲的目标根本没法表达。加权式能表达真实进展，同时手动覆盖保留了那些量不出来的目标（比如「想清楚明年的方向」）的容身之处。

# Considered Options

- **手动拖进度条**：实现最简，但年度总完成度会变成自我感觉的平均值。
- **打勾式（完成个数 / 总数）**：直观，但丢失了量纲，也无法体现各件事的分量差异。

# Consequences

- 关键结果必须有起始值，否则用户中途新建 KR 时算不出分母；起始值允许缺省为 0。
- 权重不强制校验总和为 100，界面上给出提示即可，因为中途增删 KR 会让总和临时失衡。
- 反向目标（体重从 80 降到 70）的完成度公式天然成立，不需要额外标记方向，因为目标值小于起始值时分子分母同为负。
