# 联网是可选增强，不是依赖

# Status

accepted

# Decision

这个 app 可以联网，但**联网失败必须等于没发生过**。

- 全项目只有 `src/net.py` 会发请求，别处一律不许直接调 urllib。
- 任何失败（断网、超时、对方 500、返回的不是 JSON）都返回 `None`，
  调用方继续用本地数据，界面上不出现任何异常。
- 设置里有总开关。关掉之后一个请求都不会发，功能一个都不少。
- 网络 IO 在启动时走独立线程 + 独立 sqlite 连接，不跟界面抢锁。

# Why

v1.0 把「不联网」当成了铁律，那是 CDN 的约束——图表不引 CDN 是对的，
但把它套到 API 上就过头了：节假日每年要手动补一次，外币记账压根没法算。

真正的风险不是联网，而是**联网失败时界面崩掉**。所以规矩定在失败路径上：
拿不到就当没发生，用户看不出区别。

# 接哪些接口

实测过一轮，能用的都免密钥：

| 用途 | 接口 | 结果 |
| --- | --- | --- |
| 中国节假日 + 调休 | `publicapi.xiaoai.me/holiday/year` | 可用，39 条与内置表完全一致 |
| 汇率 | `open.er-api.com/v6/latest/CNY` | 可用 |
| 食物营养 | `api.nal.usda.gov` | 连不上 |
| 食物营养 | `world.openfoodfacts.org` | 时好时坏，中文词搜出错位数据 |
| 食物营养 | `edamam` / `nutritionix` / `fatsecret` | 域名可达但都要密钥 |

# 中文食物热量改用内置表

这是同一轮实测的直接结论：**中文食物没有可靠的免费公开接口**。
Open Food Facts 搜「鸡胸肉」返回的是另一个不相干产品的营养值。

所以饮食模块的食物热量表内置在 `src/foods.py`，200+ 常见中餐与食材，
每 100g 热量带常见份量，离线可用。**不接任何食物 API**。
数据取自公开的中国食物成分表常见值，只作减脂估算参考。

# 外币记账的口径

记账流水同时存 `amount`（原币金额 + 币种）和 `amount_cny`（折算成人民币）。

统计一律读 `amount_cny`。这样折算发生在记账那一刻，之后汇率怎么动都不改写历史。
接口以人民币为基准（1 人民币 = X 外币），取倒数才是我们要的方向。

# Consequences

- 新增数据源时，必须先问「它挂了会怎样」。答案必须是「少几条数据，别的照常」。
- 每个数据源都要有一个可关闭的路子，总开关在最前面。
- 测试一律打桩，一条真请求都不发——测试不该依赖外网是否通。
