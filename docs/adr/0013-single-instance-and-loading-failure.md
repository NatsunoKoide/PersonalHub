# ADR 0013：单实例互斥与「加载中」失败兜底

日期：2026-10-24　版本：v1.5.2

## 背景

用户报告两个症状：页签永远停在「加载中…」；怀疑 24 日的数据丢了。

排查结论：

1. **数据层无辜**——用真实库的拷贝把全部后端接口跑了一遍，全部正常。
2. **卡加载的根因是两个实例并发写同一个 SQLite**：排查期间沙箱里启动的
   实例和用户自己开的实例同时运行，跨进程写锁冲突抛 `database is locked`，
   而前端 `switchTab` 的调用链上没有任何 catch——Promise 一起，加载占位
   就永远留在屏幕上，用户只能重启。
3. 数据丢失是此前已修复的测试隔离 bug（ADR 0012）造成的，与本次无关；
   24 日白天录入的数据发生在最后一次破坏性测试跑之后、当天自动备份
   （0:04）之前，没有任何备份接住，不可恢复。

## 决定

1. **同一数据家只允许一个实例**：`src/single_instance.py` 在数据家放
   `app.lock`，Windows 上用 `msvcrt.locking` 独占首字节（POSIX 用 flock）。
   锁随进程死亡自动释放，崩溃不留假锁。第二个实例弹窗说明后退出。
   锁放在 `main()` 里而不是 `build_context()` 里，测试路径完全不受影响。
2. **加载失败绝不静默**：`switchTab` 内部 catch `loadTab` 异常，渲染
   「这个页签没加载出来 + 错误信息 + 重试按钮」；导航点击 handler 再兜一层。
   引导数据（`state.boot`）就绪前忽略导航点击，避免拿空年份/空月份去请求。
3. **写锁排队上限提到 10 秒**：`db.connect` 显式 `timeout=10.0`。同进程内
   三条连接（Api / 节假日汇率同步 / 行情服务）共用一个库，短促竞争等一等
   就过去，不该动不动抛错。

## 追记（v1.5.3）：启动竞态

用户仍偶发「启动失败：接口还没就绪：bootstrap」。原因：WebView2 冷启动时
页面脚本可能跑在 Python 挂好 js_api 之前，旧版 `api()` 见桥不在就当场拒绝，
快慢全看机器当天的脸色。修法：

1. `api()` 等桥（`waitForBridge`，轮询 60ms）而不是当场拒绝；
2. `waitForBridge` 加 30 秒上限，等不到就报人话并给「重试」按钮
   （`retry-boot`），不再无限转圈。

## 追记（v1.5.4）：把启动做成「几乎必定看到内容」

用户仍觉得手动重试不够稳，要求开软件必定看到内容。进一步：
1. `waitForBridge` 监听 pywebview 官方 `pywebviewready` 事件（比纯轮询更准、
   更早拿到接口就绪信号），轮询仅作兜底，30 秒上限不变。
2. `boot()` 内部对 `bootstrap` 做 4 次指数退避重试，冷启动接口刚挂上没稳时
   自己缓过来，不再一上来就甩失败页。
3. `index.html` 的 `#view` 预置「正在启动 PersonalHub…」闪屏，开软件立刻
   有画面，不等 JS。

## 后果

- 双击两次图标不再产生两套窗口写同一个库；第二个实例会得到明确解释。
- 任何页签取数失败都有人话提示和重试入口，不会再出现无限「加载中」。
- 备份兜底：数据家 backups/ 每日一份 + 设置页「立即备份」，导出有
  JSON / CSV。这轮再次证明：破坏性操作必须先备份。
