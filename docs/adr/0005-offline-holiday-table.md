# 节假日以内置本地表为准，联网同步只往表里补数据

# Status

superseded by [0007 联网是可选增强，不是依赖](0007-networking-is-optional.md)

# Decision

节假日与调休上班日存在库里的一张自建表中，随版本预置 2026 年全年安排。

1.1.0 起可以从公开接口同步，但**本地表仍然是唯一数据源**。方向是反过来的：
不是让 app 去依赖网络，而是让网络来喂这张本地表。同步只写本地没有的日期，
你手改过的日期线上不许动它。

# Why

国务院每年 11 月左右才发布次年安排，第三方库必须每年升级包才能保持准确——
对一个自用工具来说，这意味着某年忘了升级，日历就悄悄变错，还可能是错的调休日。
所以本地表要留着，它保证十年后这 app 也不会因为某个包停更而失效。

后来实测发现免密钥的公开接口可用，于是补了一层同步，省掉每年手动录入那几分钟。
但它的定位是「往本地表里补数据」，任何失败都只是少补几条，不会让已有数据出错。

# Considered Options

- **chinesecalendar 库**：现成准确，但引入每年必须维护的升级动作，且停更即失效。
- **纯本地表**：最抗折腾，代价是每年要手动补一次 40 行数据。
- **联网拉取**：省事，但方向必须是「网络喂本地表」，否则断网或接口变更会让日历悄悄变空。

# Consequences

- 节假日数据必须可由用户编辑，否则过期的年份会变成永久错误。
- 需要一并存调休上班日，因为「假期末尾的周六要上班」无法从假期本身推出来。
- 年度热力图和日历视图都要读这张表，查询按年份区间走索引。
- 同步要能报告「哪几天和线上不一致」，让用户自己决定要不要以线上为准。
