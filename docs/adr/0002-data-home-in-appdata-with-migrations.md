# 数据家固定在 AppData，靠迁移链做到升级不搬家

# Status

accepted

# Decision

数据库、备份、配置一律放在 `%APPDATA%\PersonalHub`（即数据家），与代码目录彻底分离。库内保存 `schema_version`，每次启动按编号顺序执行尚未执行过的迁移脚本。

# Why

用户的头号诉求是「每一次更新都不用考虑迁移数据」。只要数据不在代码目录里，更新就退化成替换代码或 exe，数据文件连碰都不碰；而迁移链让结构变化在启动时自动补齐，用户全程无感。放在 AppData 还顺带满足了「别把数据文件摊在桌面上」和重装用户目录下的漫游同步。

# Considered Options

- **放在桌面项目文件夹里**：一眼能找到，但更新代码时极易误删，且桌面重装会丢。
- **文档目录**：符合规范、路径好记，但会混进用户的文档堆里。
- **便携模式（数据跟随程序）**：方便 U 盘携带，但升级时又要复制数据，与核心诉求冲突。

# Consequences

- 设置页必须常驻显示数据家完整路径、数据库体积、各表条数，并提供「打开文件夹 / 立即备份 / 另存到别处」，否则用户会失去对数据的掌控感。
- 迁移脚本只能追加不能修改，已执行过的编号永久保留。
- 每天首次启动自动备份到 `backups/`，保留最近 30 份，作为迁移失败时的退路。
